# Domain docs

This repository uses a single-context layout. Keep the glossary in `GLOSSARY.md` and architecture decision records (ADRs) in `docs/adr/`, both relative to the repository root.

Before exploring the codebase, read the glossary and the ADRs relevant to the area you will work in. Proceed when these files are absent. Use the `domain-modeling` skill to add them as terms and decisions are settled.

Use glossary terms in issues, proposals, hypotheses, and tests. If a term is missing and the project needs it, raise it during domain modeling. If a proposal conflicts with an ADR, cite that ADR and explain why the decision is worth revisiting.
